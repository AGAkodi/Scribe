# Scribe MVP audit

Audit date: 2026-11-25. Scope: the supplied `brief.md` and `todo.md`, application source, configuration, existing evidence, local automated checks, the Notion demo setup and current official SDK/provider documentation. This is an audit, not a claim that every feature has been tested on live hardware or deployed. No real provider inference or new Notion write was made during this audit.

**Follow-up 2026-11-26:** Several findings below have since been addressed in code. See `docs/progress.md` and `docs/testing.md` for the implementation and remaining validation. This document preserves the original audit findings rather than rewriting them as if they had never occurred.

## Verdict

**Scribe is an early local simulator prototype, not yet compliant with the complete MVP definition of done.** The selected technologies are broadly consistent with the brief, and individual real Notion, Deepgram, OpenRouter and simulator paths have been demonstrated. The latest flagship flow has not been demonstrated end to end with live speech and the selected free model. The frontend currently cannot be assumed to work as a packaged Even Hub app or on physical G2 hardware.

The user explicitly deferred Railway deployment; it is therefore a planned later step, while the brief's deployed-MVP criterion remains unmet.

## Evidence collected

- Current audit: `pytest tests/test_api.py -q -p no:cacheprovider`: **15 passed**, with three dependency/deprecation warnings. These tests use stubs and isolated data; they are not live end-to-end tests. `npm run build` passed TypeScript and Vite production build.
- Local isolated security test created two valid fixture sessions. Session A created a pending action; session B could read its status and cancel it (HTTP 200 for both). This demonstrates that actions are not bound to their creating session.
- Recorded prior evidence: a simulator spike rendered text, received tap/scroll and delivered microphone frames; the user later paired and transcribed live speech in the simulator. A previously confirmed simulator action returned success, and the Notion page existed with content and a matching project relation. The later free-model tests independently retrieved the fictional Chapter 4 passage, returned related responses in three runs, and saved a labelled synthetic backend test with original text, AI connection and source URLs. These are **separate tests**, not one current end-to-end run.
- Toolchain observed: Node 26.13.0, npm 11.20.0, Python 3.12.10 and Git 2.56.0; SDK 0.0.10, Even Hub CLI 0.1.14, simulator 0.7.3, TypeScript 5.9.3 and Vite 8.3.8. Node 26 is listed as LTS in the [Node release schedule](https://nodejs.org/en/about/previous-releases). The workspace is **not a Git repository** and has no CI workflow.
- Credentials were not displayed. The audit did not test physical glasses, spend on provider calls, restart the currently running backend, verify broader Notion integration permissions, or audit secret history in a remote repository.

## Priority findings

### P0 — Fix before claiming the brief's local demo is reliable

1. **Pending actions are not bound to the creator.** The action table records project and payload but no session/user identifier; the action status, cancel and confirm endpoints authenticate a caller without checking the action's owner (`services/api/scribe/main.py`, action schema and routes). The isolated two-session test proved another authenticated session can inspect and cancel the first session's action. Confirmation is also not owner-bound by inspection. This violates the explicit user/project-bound action contract; bind an action to an authenticated principal and enforce ownership on all action routes. The current single-workspace demo reduces the audience but does not satisfy the contract.
2. **Recording lifecycle is incomplete.** `apps/g2/src/main.ts` starts/stops on tap, cancel and a timer, but does not register SDK exit/disconnect/background cleanup, unsubscribe its listener, or stop recording on page teardown. The timer is started only after `audioControl(true)` resolves, so a stalled startup can delay the time limit. The brief specifically requires stopping on navigation/disconnect where supported. Actual behavior on hardware has not been observed; treat it as an unverified risk and implement/test teardown.
3. **The current flagship demo has not been tested as one flow.** The live simulator recording, real AI connection and real AI-enriched Notion write were shown in separate runs. The currently running backend was started before the free-model selection and latest changes, so prior simulator behavior cannot prove the current source. Restart with current configuration and run the advisor phrase through transcript → real retrieval → cited connection → explicit confirmation → Notion read-back; test cancel from the same UI. A real Deepgram request may consume credits, so follow the user's approval instruction.
4. **The AI can still assert unsupported facts.** The API verifies that IDs in `source_ids` belong to retrieved chunks, not that the generated statements follow from those chunks. It also accepts and saves the AI summary even when `connection_type` is `none` and no citation is returned. Earlier free-model runs misclassified an unknown motive as a conflict. Limit or validate uncited summaries, clearly distinguish hypothesis from fact, and test adversarial source text and contradictions; model validation is not a proof of factual grounding.
5. **Recall and brainstorming are menu labels, not completed workflows.** The client sends a different `mode`, but the backend shares one capture prompt and response schema; there is no distinct question-answer contract, saved follow-up or selected suggestion, or bounded conversation history. The write payload always saves the original spoken transcript plus generic AI text. The brief's P1 acceptance is not met; hide/label these modes or complete and test them after P0.
6. **The Notion write preview and metadata are incomplete.** The client reviews transcript, summary, connection and snippets, but the generated title/category are not displayed. The write uses the first 80 characters of the transcript as `Name`, ignores generated category and title, and puts AI material in body paragraphs rather than populating the Ideas database's matching properties. The receipt shows an ID rather than the page title/link. Align the immutable preview with the actual write and verify the saved metadata.
7. **Retrieval can silently omit relevant text.** `read_blocks` cuts each block at 2,000 characters, has fixed recursion/page/block limits and does not report truncation or unsupported types. There is no short-TTL cache/refresh. A match only proves lexical overlap, not comprehensive project knowledge. Preserve/split long content and communicate bounded coverage; test pagination, unsupported blocks, revoked access and no-match.

### P0 before packaged/hosted use; deployment deferred by user

8. **Even Hub network permission is absent.** `apps/g2/app.json` declares `g2-microphone` but no `network` permission or backend whitelist. The official [Even Hub networking documentation](https://hub.evenrealities.com/docs/build/networking) says both the manifest whitelist and server CORS must allow the origin. Simulator HTTP success does not validate actual phone-side permissions. Add the exact backend HTTPS origin when it exists, configure CORS, rebuild and test the package.
9. **The current connection defaults are local-only.** The setup defaults to `http://localhost:8000`, and the client rejects non-HTTPS remote addresses. On a phone, localhost refers to the phone, not this computer. The frontend does not currently use `VITE_API_BASE_URL`; phone-to-backend reachability, HTTPS, pairing, CORS and the packaged origin are unverified. The official [local testing flow](https://hub.evenrealities.com/docs/test/local-testing) uses a LAN-reachable development URL and QR code; it does not validate packaged permissions or locked-phone behavior.
10. **No persistent deployment or reproducible package has been verified.** SQLite defaults to a local path; no Railway volume or hosted service exists. The previous `.ehpk` was built before later changes and emitted an SDK-version warning. The [packaging documentation](https://hub.evenrealities.com/docs/ship/packaging) recommends passing the bundled SDK version to derive the correct phone-app floor. The manifest's `min_app_version` is 2.0.0, below the floor previously stamped by the CLI. Rebuild with verified version and manifest, then test packaged/private or beta behavior as appropriate.
11. **Request limits and isolation are not production-ready.** The rate limiter is an in-memory per-process dictionary. The size guard trusts `Content-Length`; the multipart parser can receive a request without that header before the endpoint reads 960,001 bytes. Audit streaming body limits, proxy/IP behavior, rate limiting, error messages and sessions before public exposure. The default Vite configuration binds to all interfaces (`host: true`); keep local development on loopback unless deliberately testing a secured LAN.
12. **No Git repository, CI, or secret-history check exists.** `.gitignore` and a placeholder `.env.example` are present, but `git status` reports this is not a repository. There is no CI or verified clean-checkout setup. Before publishing, initialize the intended repository, review what will be tracked, verify no secrets or audio are included, and configure checks. No assertion about remote history can be made because no remote repository was found.

## Resource and G2 integration assessment

- **Architecture:** Vite/TypeScript, Even Hub SDK, FastAPI, Notion, Deepgram and OpenRouter match the brief. Railway is not yet used; Supabase is optional and not required for the chosen single-instance architecture.
- **Display and events:** The app initializes `waitForEvenAppBridge`, uses one `TextContainerProperty` with `isEventCapture: 1`, and handles system/text envelopes separately with the omitted zero-valued click fallback. This agrees with the [official starter's event pattern](https://github.com/even-realities/evenhub-templates) and [display/container rules](https://hub.evenrealities.com/docs/build/display). The latest pagination, wrapping and gesture handling have not been manually verified in a current simulator session.
- **Audio:** The implementation calls `audioControl(true)` only after a gesture and converts 16 kHz, mono, signed 16-bit PCM to WAV for Deepgram. The [Even Hub device documentation](https://hub.evenrealities.com/docs/build/device-apis) documents those defaults and format, and [Deepgram's prerecorded guide](https://developers.deepgram.com/docs/pre-recorded-audio) accepts WAV with token authentication. Actual G2 microphone and lifecycle behavior have not been tested; the desktop simulator used the computer's microphone.
- **Notion:** The backend uses a token, versioned API, project database query, bounded block traversal, confirmed page creation and capture-ID reconciliation. Prior live tests verified the pinned version for the demo workspace. It does not retry 429/temporary failures, cache retrieval, retain all long text, or establish arbitrary workspace compatibility.
- **OpenRouter:** The chat completion request uses a JSON schema and `require_parameters` consistent with [OpenRouter's structured-output documentation](https://openrouter.ai/docs/guides/features/structured-outputs). Local validation verifies source IDs against retrieved chunks, not semantic accuracy. The selected free model produced three useful repeated fictional tests and one saved demo note; those samples do not guarantee uptime, quality or safety under prompt injection.
- **Packaging:** `g2-microphone` is declared, but `network` is missing. SDK 0.0.10 is resolved in the lockfile while `package.json` uses ranges for SDK/CLI/simulator. The previous package is stale. Simulator, local hardware testing, private testing and beta/reviewer parity are separate modes; see [Even Hub testing](https://hub.evenrealities.com/docs/test).

## Recommended order

1. Bind actions to the creating session, add microphone/lifecycle cleanup and close the upload/retention gaps; add regression tests.
2. Make the preview match the exact Notion payload, improve evidence/summary handling, and preserve long source text. Decide whether to hide incomplete P1 modes during the P0 demo.
3. Restart the backend so it loads current code and the free model. Run the actual advisor story through the current simulator with explicit confirmation, inspect the Notion page and test cancellation, duplicate taps, no-match, rate limit and network loss. Obtain approval before any additional potentially billable transcription.
4. When the user wants deployment, configure an actual HTTPS backend, origin-specific network permission, persistent storage, CORS, and a current package; validate on the phone/glasses if hardware exists.
5. Verify the current organizer rules directly, create the repository and reproducible setup, perform the remaining QA matrix and prepare video/submission material. The previously reported November 29 20:59 Lagos deadline is third-party information, not independently confirmed; the supplied DoraHacks listing returned HTTP 405 to the audit reader.
